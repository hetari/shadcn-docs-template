This guide walks you through every touchpoint you need to personalize this template — from navigation links to the command menu search palette.

## Site Configuration

The central place for branding and links is `app/lib/siteConfig.ts`. Update these values **first**:

```ts
// app/lib/siteConfig.ts
export const siteConfig: SiteConfig = {
  name: "My Project", // shown in header & OG tags
  url: "https://my-project.dev",
  ogImage: "https://my-project.dev/og.jpg", // social sharing image
  description: "A short description of your project.",
  links: {
    github: "https://github.com/you/my-project",
    githubAPI: "https://api.github.com/repos/you/my-project",
    ungh: "https://ungh.cc/repos/you/my-project",
  },
};
```

## Navigation & Sidebar Configuration

Navigation in this template is controlled through constants and configuration in `app/lib/navigation.ts`. Desktop (`DocsSidebar.vue`) and mobile (`MobileNav.vue`) share the same configuration through the `useSidebarSections` composable, ensuring both surfaces remain in sync.

### How the Sidebar Works

The sidebar consists of two layers:

1. **Pinned Sections / Quick Links (Optional)**: Configured in `app/lib/navigation.ts` via `NAV_SECTIONS` and `SIDEBAR_SECTIONS_LABEL`. When configured, these appear at the very top of the sidebar.
2. **Content Tree (Automatic)**: Automatically built from your markdown files and directories in `content/docs/`.

```
┌──────────────────────────────────────────────┐
│  [SIDEBAR_SECTIONS_LABEL] (e.g. Quick Links) │ ◄── NAV_SECTIONS (optional pinned links)
│  • Interactive Demo                          │
├──────────────────────────────────────────────┤
│  Getting Started                             │ ◄── content/docs/1.getting-started/
│  • Introduction                              │
│  • Installation                              │
├──────────────────────────────────────────────┤
│  Customization                               │ ◄── content/docs/2.customization/
│  • Customizing the Template                  │
│  • MDC Components                            │
│  • Composables                               │
│  • Writing Documentation                     │
├──────────────────────────────────────────────┤
│  Components                                  │ ◄── content/docs/3.components/
│  • Components                                │
│  • DocTabs                                   │
│  • ...                                       │
└──────────────────────────────────────────────┘
```

### Avoiding Duplicate Links

::callout{type="tip"}
**Why is `NAV_SECTIONS` empty by default?**  
Your content files in `content/docs/1.getting-started/` already create a "Getting Started" group with "Introduction" and "Installation". By leaving `NAV_SECTIONS = []`, your sidebar cleanly displays only the content folders without duplicating "Get Started" and "Installation" at the top!
::

If you add a page to `NAV_SECTIONS` that already lives inside a content folder, the template automatically hides it from the folder group below (`autoExcludeSectionsFromGroups: true` in `SIDEBAR_CONFIG`), so it will **never duplicate**.

### Navigation Configuration (`app/lib/navigation.ts`)

All navigation settings live in `app/lib/navigation.ts`:

```ts
// app/lib/navigation.ts

/** Top navbar links (desktop header and mobile menu) */
export const MAIN_NAVIGATION: NavItem[] = [
  { href: "/docs/getting-started/introduction", name: "Docs" },
  { href: "/docs/components", name: "Components" },
];

/** Label displayed above the pinned section links (default: "Sections") */
export const SIDEBAR_SECTIONS_LABEL = "Sections"; // or "Quick Links", "Featured"

/**
 * Pinned quick links shown at the top of the sidebar and mobile menu.
 * Leave empty [] for a clean, folder-only sidebar without duplicates.
 */
export const NAV_SECTIONS: NavItem[] = [
  // Example pinned links:
  // { name: "Demo", href: "/docs/prose-demo", icon: "sparkles" },
];

/** Sidebar folder group titles (lowercased) to completely hide from sidebar */
export const SIDEBAR_EXCLUDED_SECTIONS: string[] = [];

/** Specific page paths to hide from the sidebar tree */
export const SIDEBAR_EXCLUDED_PAGES: string[] = [];

/** Unified sidebar configuration */
export const SIDEBAR_CONFIG = {
  sectionsLabel: SIDEBAR_SECTIONS_LABEL,
  sections: NAV_SECTIONS,
  excludedSections: SIDEBAR_EXCLUDED_SECTIONS,
  excludedPages: SIDEBAR_EXCLUDED_PAGES,
  autoExcludeSectionsFromGroups: true, // Prevents duplicate links
};
```

| Constant / Property            | Description                                                   | Used By                                 |
| ------------------------------ | ------------------------------------------------------------- | --------------------------------------- |
| `MAIN_NAVIGATION`              | Main navigation links in header                               | `MainNav.vue`, `MobileNav.vue`          |
| `SIDEBAR_SECTIONS_LABEL`       | Title label above pinned links (e.g., "Quick Links")          | `DocsSidebar.vue`, `MobileNav.vue`      |
| `NAV_SECTIONS`                 | Pinned quick links array at top of sidebar                    | `DocsSidebar.vue`, `MobileNav.vue`      |
| `SIDEBAR_EXCLUDED_SECTIONS`    | Hides entire sidebar groups by folder title (case-insensitive)| `DocsSidebar.vue`, `MobileNav.vue`      |
| `SIDEBAR_EXCLUDED_PAGES`       | Hides specific pages by route path                            | `DocsSidebar.vue`, `MobileNav.vue`      |
| `SIDEBAR_CONFIG`               | Unified configuration object bundling all sidebar options     | `useSidebarSections.ts`                 |

### Organizing Content Folders & Pages

Nuxt Content builds your sidebar hierarchy from `content/docs/`:

1. **Ordering Folders & Pages**: Use numeric prefixes to control the ordering:
   - Folders: `1.getting-started/`, `2.customization/`, `3.components/`
   - Files: `1.introduction.md`, `2.installation.md`
   *(Nuxt Content automatically strips the numeric prefixes from the final URL path)*.

2. **Custom Group Names**:
   - By default, folder names are converted to titles (e.g. `1.getting-started` becomes "Getting Started").
   - To customize the folder's title or icon, add a `.navigation.yml` inside the folder:
     ```yaml
     # content/docs/1.getting-started/.navigation.yml
     title: Getting Started
     icon: square-play
     ```

3. **Custom Page Title in Sidebar**:
   If a page's `<h1>` title is long (e.g., "Overview of Built-in Components") but you want a short label in the sidebar (e.g., "Overview"), add `navigation.title` to the page's YAML frontmatter:
   ```yaml
   ---
   title: Overview of Built-in Components
   navigation:
     title: Overview
     icon: blocks
   ---
   ```

4. **Sidebar Badges and Icons**:
   Add indicators directly in the page frontmatter:
   ```yaml
   ---
   title: DocTabs
   navigation:
     icon: panels-top-left
   new: true    # Displays green dot indicator
   beta: true   # Displays orange dot indicator
   soon: true   # Displays "Soon" badge
   hide: true   # Completely hides this page from the sidebar
   ---
   ```

### Hiding Groups and Pages

There are three easy ways to hide items from the sidebar:

1. **Hide a single page via frontmatter**: Add `hide: true` in the markdown frontmatter:
   ```yaml
   ---
   title: Secret Draft
   hide: true
   ---
   ```
2. **Hide specific paths via config**: Add the route path to `SIDEBAR_EXCLUDED_PAGES` in `app/lib/navigation.ts`:
   ```ts
   export const SIDEBAR_EXCLUDED_PAGES: string[] = ["/docs/prose-demo"];
   ```
3. **Hide an entire group**: Add the group title (lowercase) to `SIDEBAR_EXCLUDED_SECTIONS` in `app/lib/navigation.ts`:
   ```ts
   export const SIDEBAR_EXCLUDED_SECTIONS: string[] = ["archive", "drafts"];
   ```

### Mobile Navigation

**File:** `app/components/MobileNav.vue`

The mobile menu opens a slideout panel with:
1. **Menu Section**: The "Home" link and all items from `MAIN_NAVIGATION`.
2. **Pinned Sections**: The items from `NAV_SECTIONS` (if any are configured).
3. **Content Tree**: The full documentation hierarchy matching the desktop sidebar.

## Command Menu Search

**File:** `app/components/CommandMenu.vue`

The command palette opens via :ContentKbd[⌘ K] (Mac) or :ContentKbd[Ctrl K] (Windows/Linux). It uses a hybrid search model combining static navigation items and dynamic API results.

### How it works

1. **Static Navigation**: Items from `MAIN_NAVIGATION` and the documentation tree are passed as props from `SiteHeader.vue`.
2. **Dynamic Search**: Real-time results are fetched from `/api/search` via the `useSearch` composable as you type.
3. **Actions**: Special commands like "click to copy" are hardcoded within the command list.

### Adding Custom Items to Search

To add custom searchable items that aren't documentation pages:

1. **Static Groups**: Add a new `<CommandGroup>` inside `<CommandList>` in `CommandMenu.vue`.
2. **Global Search**: Ensure your data is indexed in the search backend if you want it to appear in the "Search Results" section.
3. **Prop Injections**: If you want to pass local data, add a new prop to the `Props` interface in `CommandMenu.vue` and populate it from `SiteHeader.vue`.
